# 7 日开发路线图

本计划用于连续推进一个独立的新项目。Day 1–Day 7 是执行顺序，不代表这些工作已经发生，也不代表持久后台任务已经启动。每次恢复时先检查 [HANDOFF.md](HANDOFF.md)，依据实际产物和验收结果继续。

所有阶段保持 Node.js 22+、零第三方依赖、离线运行。相同输入、seed、策略及配置应得到可核验的相同结果。新增功能必须建立在上一阶段已验收的产物上。

## 每日增量与验收

| 阶段 | 依赖 | 有意义的增量 | 验收命令与完成条件 |
| --- | --- | --- | --- |
| Day 1：确定性内核 | 无 | 输入校验；单 worker、非抢占环境；自动 idle 推进；等待时间 reward；FIFO CLI；最小示例；基础测试；使用说明 | `npm test`、`npm run demo`、`node src/cli.mjs examples/tiny.json --policy fifo`。tiny 结束时间 9、总等待 2、busy 6、idle 3；重复运行一致。 |
| Day 2：基准与公平性 | Day 1 的状态转移和指标 | 提取共享策略接口；比较 FIFO 与 SJF；定义确定性 tie-break；补充每任务等待时间、最大等待等公平性指标 | `npm test`，以及实现后的 `node src/cli.mjs examples/tiny.json --policy sjf`。覆盖能区分两策略的输入，核验指标与排序，说明 SJF 的等待时间权衡。 |
| Day 3：固定 seed 工作负载 | Day 2 的策略及指标 | 实现可复现伪随机生成器；保留 seed 和生成参数；加入不同负载强度、突发及空闲间隔 fixtures | `npm test`。同 seed、参数生成相同输入；不同 seed 产生可区分样本；生成输入均通过校验；固定 fixtures 可用 CLI 离线运行。 |
| Day 4：批实验与结果 | Day 3 的固定输入集合 | 批量比较基准策略；输出逐次原始 JSON 和汇总；记录输入、seed、策略、配置和指标定义 | `npm test`；增加并运行文档化的批实验命令。重跑固定批次得到相同数据；汇总可从原始结果重算；输出不能混入机器凭据或用户文件。 |
| Day 5：策略扩展与对照 | Day 4 的实验工具 | 固定策略扩展约定；增加带等待时间权重的贪心策略；在相同输入上与 FIFO、SJF 对照 | `npm test`；运行 Day 4 的批实验命令比较全部策略。策略仅选择合法就绪动作；给出改善和退化案例，不承诺训练效果或全局最优。 |
| Day 6：回归与指标核验 | Day 5 的完整策略集合 | 补齐边界、非法动作、reset、观察隔离及回归；用手算 fixtures 和固定 seed 属性检查交叉核验指标 | `npm test`；重跑固定实验批次。任务各完成一次；时间单调；busy 等于总 duration；等待时间与累计 reward 一致；归档已解决问题和仍有限制。 |
| Day 7：可复现实验报告 | Day 6 的通过验收版本 | 写实验方法、结果、限制与复跑步骤；整理输入和原始结果；验证干净目录下的离线使用；准备可交付版本 | `npm test`、`npm run demo`、文档化的批实验命令。报告每项结论能追溯到结果；无第三方依赖下载；实际 commit/push 与远程结果完成核验。 |

Day 2 及以后出现的新命令、策略名和产物路径，须在实现后补进 README。表中的批实验命令尚未实现，不能当作当前可运行命令。

## 每日工作与提交规则

1. 阅读交接记录，检查工作区改动、当前 commit 和当天日期；不要覆盖他人的未提交改动。
2. 完成当前阶段的可运行增量，执行阶段验收；若失败，先修复或在交接中明确记录阻塞。
3. 更新交接记录，填写实际命令、结果、限制和下一步。只有真实计时记录才能用于工时统计。
4. 检查待提交文件仅为本项目产物，不包含凭据、个人数据、外部私有文档或旧项目内容。
5. 在 Git 身份和发布目标已核实后提交当天的真实改动，再推送授权的远程仓库，核验本地与远程 SHA。CI 已运行时记录结果；未运行或失败时如实说明。

不通过增加文件数、行数、空提交或回填提交时间满足日程。若一天没有可验收增量，交接记录说明原因，日程状态保持真实。GitHub 登录或推送受阻时，可继续本地实现和测试，但不能写成已经发布。

## 可恢复性要求

每个阶段结束时，交接记录必须回答：当前有哪些可用功能，哪组测试实际跑过，哪些文件尚未提交，远程发布是否已核验，以及下一次首先应做什么。后续执行者据此恢复，不依赖聊天历史。

实验产物保留输入、seed、策略及版本信息。可复现比较使用相同输入和相同指标定义；墙钟运行时若用于辅助观察，应与确定性仿真指标分开记录。
